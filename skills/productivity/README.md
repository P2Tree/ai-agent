# Productivity

提升效率但不直接写代码的 skill。

## brainstorming `[自动]`

写代码之前先对齐需求。先读项目和已有上下文再提问；只在答案会改变要构建的东西时提问，其余作为可修正的提案。逐段复述确认，按工作量决定 design doc 规模，写完后先过 builder check，再请你批准。支持可视化原型辅助讨论。

**什么时候用：** 开始新功能、新项目、或大改动之前。

**触发方式：** agent 检测到你开始做新功能或大改动时自动触发。

**参考：** superpowers:brainstorming

## prototype `[自动]`

快速做个一次性原型来验证设计思路。逻辑原型是单个可分享 HTML 文件（自由操作 + 引导式 walkthrough），UI 原型做多个可切换变体。原型本身提交到 throwaway branch 作为一手证据，主分支只保留验证后的决策。

**什么时候用：** 想快速验证设计思路、数据模型、或 UI 方案时。

**触发方式：** 当说"做个原型""试试几种方案""prototype this"时会激活。

**参考：** mattpocock:prototype

## grill-me `[自动]`

像面试一样追问，帮你把模糊的想法理清楚。按轮次推进：每轮把当前 frontier（前置条件已满足的问题）一次性列出，每题编号并给推荐答案；事实由 agent 自己查，决策留给你。frontier 清空且你确认后才行动。

**什么时候用：** 有了个想法但还没想透，想让 agent 帮你捋清楚时。

**触发方式：** 需要你说"grill me""帮我压力测试一下这个方案"或输入 `/grill-me` 才会激活。

**参考：** mattpocock:grill-me + mattpocock:grill-with-docs

## research `[自动]`

把一个研究问题交给后台 agent：查官方文档、源码、规范、第一方 API 等高可信一手来源，把结论写成一份带引用的 Markdown 文件放进仓库。你继续做别的事，它负责阅读和整理。

**什么时候用：** 结论需要留存/引用、阅读量大到会污染主会话、或需要并行调研时。

**什么时候不用：** 一次搜索或读一个文件就能回答；事实已经在仓库或对话里；问题其实是产品决策而不是事实调查。

**触发方式：** 你说要调研、查资料、核实某个技术事实时，agent 自动激活。

**参考：** mattpocock:research
