# Step 4: Generate the architecture design document

严格按照 template.md 的章节顺序和格式生成文档。

## 必选章节

| 编号 | 章节 | 核心内容 |
|------|------|---------|
| 1 | 背景和现状 | 项目定位、解决的问题、当前状态、与同类系统的关系、痛点（Observation/Root Cause/Mitigation 三段式） |
| 2 | 设计目标 | 以表格列出，每个目标一句话说明 + 优先级（P0/P1/P2） |
| 3 | 总体结构 | ASCII 架构图 + 分层说明 |
| 4 | 分模块结构 | 每个核心模块一节：职责、关键类/函数、核心数据、源文件路径 |
| 5 | 数据流关系 | 核心数据流的 ASCII 流程图 + 关键路径的文字描述 |
| 6 | 源代码组织结构 | 目录树 + 每个目录/关键文件的用途说明 |
| 7 | 通信 | 模块间/进程间/与外部系统的通信方式和协议（表格） |
| 8 | 关键数据结构 | 核心数据结构的表格（名称、层级、数量/大小、说明） |
| 9 | 异常处理 | 异常分类、传播机制、错误码体系 |
| 10 | 报告输出 | 系统产生的所有输出（trace、日志、统计、比对结果等） |
| 11 | 外部接口 | CLI 参数、库 API、环境变量，以表格列出 |
| 12 | 依赖项说明 | 外部依赖表格（名称、类型、用途、获取方式） |
| 13 | 测试策略 | 测试框架、执行方式、编写规范、覆盖范围、CI 集成 |
| 14 | 影响和限制 | 不支持的功能（表格：特性/说明/支持计划）、性能限制、已知差异 |
| 15 | 术语表 | 术语 / 全称 / 说明 三列表格 |

## 可选章节

根据项目特征，在章节 14 之后、术语表之前，可增加以下章节：

- 同类系统对比（Simulator vs CModel、Compiler vs Interpreter 等）— 用对比表格逐项列出差异
- 不支持的硬件/平台特性表格 — 包含特性、说明、支持计划三列
- 常见问题排查 — 使用前自查清单 + 常见运行时错误表格
- 安全考量
- 性能特征
- 发布与部署

## 编写规范

- **架构图用 ASCII art**：使用方框（`┌─┐`）、箭头（`──▶`）、缩进表示层次关系。确保在等宽字体下可读。
- **表格优先**：设计目标、寄存器、内存层次、依赖项、CLI 参数、环境变量、错误码等，一律用 Markdown 表格。同类系统对比用对比表格，不要只用文字描述。
- **标注源文件路径**：在模块标题后标注关键源文件，如 `### 4.1 BirenSimulator（simulator.h/cpp）`。
- **数据流用流程图**：ASCII 流程图展示输入→处理→输出的完整路径，分支用缩进或平行箭头。
- **痛点用三段式**：Observation / Root Cause / Mitigation，参考 template.md 1.3 节格式。
- **不写空话**：每个章节必须有实质内容。如果某个章节暂时无法填充，写"待补充"而不是用空话填充。性能/精度目标填实际数值，不得留空占位符。
- **中文撰写**：技术术语保留英文原文，说明文字用中文。
- **修订历史**：文档开头包含 Revision History 表格，记录每次变更。
