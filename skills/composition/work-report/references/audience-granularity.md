# 受众维度

同一份报告，面向不同受众需要调整深度、框架和数据呈现方式。撰写前必须确认汇报对象。

## 三级受众

### 直属上级（直接管理者）

- **关注点：** 执行细节、阻塞项、资源需求
- **数据深度：** 细粒度，到具体任务和指标
- **问题呈现：** 直接说明阻塞原因，明确需要什么支持
- **计划呈现：** 具体到本周/本日行动
- **篇幅：** 中等，可包含技术细节
- **语气：** 平实、直接，可使用团队内部术语

### 团队负责人（跨团队视角）

- **关注点：** 跨团队依赖、整体进度、资源协调
- **数据深度：** 聚合指标，趋势为主，省略单任务细节
- **问题呈现：** 侧重跨团队协调需求，标注依赖方
- **计划呈现：** 里程碑级别，强调协同点和交付节点
- **篇幅：** 中等偏短，省略执行细节
- **语气：** 专业、精炼，避免过于内部的术语

### 高层（部门负责人及以上）

- **关注点：** 战略对齐、风险暴露、关键决策点
- **数据深度：** 3-5 个核心指标 + 红绿灯状态（已达标/有风险/需关注）
- **问题呈现：** 风险点 + 影响范围 + 需要的决策，不展开技术细节
- **计划呈现：** 季度/年度方向，不列具体任务
- **篇幅：** 简短，1-2 页
- **语气：** 高度精炼，每个字都要有价值

## 调整策略

同一份报告，按受众调整以下维度：

| 维度 | 直属上级 | 团队负责人 | 高层 |
|------|---------|-----------|------|
| 指标粒度 | 具体任务级 | 聚合模块级 | 核心结果级 |
| 进展描述 | 逐项列举 | 按模块汇总 | 按战略主题 |
| 问题篇幅 | 详细原因+方案 | 影响范围+协调方 | 风险定性+需决策 |
| 计划粒度 | 日/周级行动 | 里程碑级 | 季度/年度方向 |
| 数据呈现 | 完整表格 | 关键行高亮 | 红绿灯状态 |
| 闭环章节 | 逐条状态 | 异常项标注 | 仅列偏差项 |

## 混合受众

当报告同时面向多级受众时（如项目周报抄送多方）：

1. 主体按**最高决策者**的粒度撰写
2. 在附录或子章节提供细粒度数据供直属上级查阅
3. 明确标注哪些章节面向哪级受众（如"以下内容供技术团队参考"）
