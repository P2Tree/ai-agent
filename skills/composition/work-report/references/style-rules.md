# 中文企业汇报风格规则

## 1. 无 emoji

任何位置都不使用 emoji，包括标题、段落、列表、表格。

用文字标记状态：完成 / 进行中 / 未开始，或 已达标 / 有风险 / 需关注。

## 2. 数据必须

每个结论必须有数据支撑。禁止出现"进展顺利""效果良好"等无数据表述。

改写示例：

| 原始表述 | 改写后 |
|---------|-------|
| 用户增长情况良好 | 用户数 12.3 万，环比 +8.2%，目标达成率 103% |
| 系统性能有所提升 | P99 延迟从 320ms 降至 185ms，降幅 42% |
| 客户满意度提高 | NPS 从 32 升至 45，环比 +40.6% |

## 3. 对比基准

数据必须带对比维度，三选一或组合：

- **vs 上期**（环比）— 最常用，展示趋势
- **vs 目标**（达成率）— 展示执行质量
- **vs 行业**（竞争位）— 展示外部定位，非必需

孤立的数字（如"用户数 12.3 万"）需要补充对比才有意义。

## 4. 表格优先

数据密集的内容用表格呈现，不用段落罗列。

- **表格用于**：指标、进度、对比、计划清单、目标达成
- **段落用于**：背景说明、风险分析、行动方案、经验反思

表格规范：
- 数字右对齐，文字左对齐
- 表头加粗
- 同列数据单位一致，单位写在表头不在单元格内

## 5. 问题表述

不使用"问题""失败""错误"等负面词汇，替换为：

| 原始表述 | 替换为 |
|---------|-------|
| 问题 | 风险点 |
| 失败 | 未达预期 |
| 错误 | 待改进项 |
| 困难 | 待协调事项 |
| 阻塞 | 需要支持的方向 |

每个风险点/待协调事项必须附带：
1. 影响范围
2. 建议方案
3. 需要的支持（责任人/资源/决策）

不能只列问题不给方案。

## 6. 计划闭环

计划必须包含 **责任人 + 截止日期**。

必须闭环上期承诺：
- **已完成** → 标注完成状态和结果数据
- **进行中** → 标注当前进度百分比和预计完成时间
- **未完成** → 标注原因和调整方案

不允许上期承诺无声消失。

## 7. 语言风格

- 简洁、直接、无修辞
- 不用比喻、不用感叹号
- 不用"非常""极大""显著"等程度副词——用量化替代
- 一句话只说一件事
- 被动语态优于主动语态时使用被动（"XX 已完成"优于"我完成了 XX"，视受众而定）

## 8. 排版规范

- 标题层级：# 一级 / ## 二级 / ### 三级，不跳级
- 列表：用 `-` 不用 `*`
- 加粗用于关键指标和状态标记，不用于强调语气
- 表格与段落之间空一行
- 多个表格之间不用空行之外的额外分隔
