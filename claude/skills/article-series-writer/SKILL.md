# Article Series Writer

并行编写系列文章并自动 review 闭环的工作流，适用于知乎/公众号等平台的长文系列创作。

## 适用场景

- 有系列文章大纲，需要快速生成多篇内容
- 有统一的行文风格要求，需要自动检查
- 需要多人/多 subagent 协作完成写作任务

## 工作流程

### 1. 任务分析

读取大纲文件，识别：
- 总文章数 n
- 每篇文章的核心主题和预计字数
- 贯穿全系列的核心类比（如"厨房/米其林大厨"体系）
- 系列统一的风格要求

### 2. 写作阶段（并行）

为每篇文章创建独立 subagent，传递：
- 对应的大纲段落
- 风格指南（如 P2Tree 文风）
- 统一的类比体系
- 必含内容清单（如 Agent、Subagent 概念）

**输出路径**：`articles/part_N.md`（或自定义命名）

### 3. Review 阶段（串行）

创建两个独立 review subagent：

**风格审查**：
- 开篇类型（亲历叙事/坦白犹豫/画面唤起）
- 类比一致性（关键词替换检查，如"帮厨"→"米其林大厨"）
- 句式修辞（"虽然...但..."转折、强调句独立成段）
- 结尾风格（谦逊安抚/哲思收束 + 下一篇预告）

**正确性审查**：
- 对照大纲检查内容完整性
- 技术准确性（命令语法、文件路径、API名称）
- 表格/代码正确性

### 4. 修复阶段

根据 review 结果修复：
- 优先处理**跨文章的一致性问题**（术语替换、类比漂移）
- 再处理单篇文章的局部问题

### 5. 输出报告

汇总：
- 各篇文章审查结果
- 已修复的问题列表
- 遗留问题（如有）

## 常见问题处理

### Review agent 超时

原因：审查任务过重（读取 5+ 篇长文 + 分析）

解决：
- 将完整报告写入临时文件，主 agent 读取文件汇总
- 或设置更长的 timeout

### 跨文章术语不一致

解决：在 review 完成后、修复开始前，先做一轮全局搜索替换：
```bash
# 如替换"帮厨"为"米其林大厨"
sed -i 's/帮厨/米其林大厨/g' articles/*.md
```

### 部分 subagent 失败

解决：
- 检查具体 agent 的错误信息
- 手动重写失败的文章段落
- 使用 SendMessage 恢复失败的 agent

## 示例：启动写作任务

```
请基于 /home/user/draft/ 目录下的系列大纲，并行生成 5 篇文章：
- 输出到 /home/user/articles/
- 遵循 P2Tree 文风指南
- 统一使用"厨房/米其林大厨"类比体系
```
